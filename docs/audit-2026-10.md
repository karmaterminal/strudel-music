# strudel-music audit, 2026-10

Done for #65 ("Resurrect strudel-music"). `main` was audited at `1bab7d6` (2026-04-17) on
2026-10-03, from a clean clone in a cloud container. Every number below comes from a command in
the proof log at the end.

## Summary

- **A clean checkout works.** Setup, the smoke test and a render succeed, and the render passes
  the QA gate: `fog-and-starlight`, 16 cycles, 64 s of audio in under a second, −14.4 LUFS, true
  peak −3.0 dBFS, no dropouts.
- **Fixed in #73:**
  - Both renderers played a number in `note()` as Hz instead of a MIDI note.
  - `dispatch.sh play` ignored its channel argument.
  - The ignore rules kept `samples/strudel.json` out of the ClawHub bundle.
  - `SKILL.md` metadata that OpenClaw and ClawHub reject or drop.
  - An onboarding example that didn't render as written.
  - A CI secret-scan check that could never fail.
- **Fixed for #66 (2026-10-05):** 9 of 15 shipped compositions named sounds setup never
  installed. Now every shipped composition plays the sounds it names, in both renderers, and CI
  renders each one with `--strict`, which fails on a missing sound, a dropped event or a Strudel
  warning (D8–D10). Review of that fix found that the snare and cowbell had never sounded: both
  renderers read their 32-bit float files as silence (D22). It also found bad input passing
  quietly (D23, D24).
- **Fixed for #69 (2026-10-05):** CI no longer publishes to ClawHub. figs publishes each release
  by hand, after a dry run from a fresh clone and a check of its file list (`CONTRIBUTING.md`
  § Releasing). The clawhub devDependency is gone, and `npm audit` reports nothing (D13, D14).
- **Fixed for #75 (2026-10-06):** samples looped, cut short or restarted where Strudel plays
  them once (D21). Both renderers now follow Strudel's rule, and the layers meant to sustain say
  `.loop(1)`, so they sound as before.
- **Still broken, with issues filed:**
  - Two renderers that disagree (#67).
  - No reverb, delay, highpass or distortion (#68).
  - Repo hygiene (#72).
  - Work stranded on branches (#61, reopened).
- **Checked on 2026-10-03 (#70):** the live ClawHub release, 1.2.2, installs, sets up, renders,
  passes the QA gate and uninstalls cleanly. A Git install of `main` installs, sets up, renders
  and passes the QA gate too. Once setup has run, `openclaw skills update` needs `--force`, and
  setup has to run again (§ OpenClaw).
- **Not verified:** voice streaming. It needs a bot token and a voice channel. Its argument
  passing has a test now.

- **Command name.** OpenClaw sanitizes the skill name to `strudel_music` (`sanitizeSkillCommandName`).
- **Install.** Per OpenClaw's docs (`docs/cli/skills.md`):
  - `openclaw skills install git:karmaterminal/strudel-music` installs from Git. It needs
    `SKILL.md` at the repo root, as here.
  - `openclaw skills install @karmafeast/strudel-music` installs from ClawHub.
  - `openclaw skills check` lists missing requirements.
  - Removal uses the ClawHub CLI: `clawhub --workdir <workspace> uninstall @karmafeast/strudel-music`.
- **Setup after install.** Installing copies files only, so `npm run setup` must run in the
  installed folder. SKILL.md says so.
- **Exec.** A long `exec` moves to the background after `yieldMs` (10 s by default). `background`
  and `timeoutSeconds` are the current parameters, and `sessions_spawn` takes `mode` and
  `runTimeoutSeconds`.
- **Run on 2026-10-03 (#70; proof log):**
  - **ClawHub, 1.2.2.** Install, `skills check`, setup, smoke test, render, QA gate and uninstall
    all work. The install prints ClawHub's audit box ("Outcome: Review") and goes ahead.
  - **Git, `main` 264c7fb.** Install, `skills info`, setup, smoke test, render and QA gate work.
    Unit tests: 8 pass, and the 4 bundle-rule tests skip because the install has no `.git`.
    OpenClaw records the commit in `.openclaw/source-origin.json`. Neither `skills update` nor
    `clawhub uninstall` tracks a Git install: reinstall with `--force`, or delete the folder.
  - **Update.** OpenClaw fingerprints every file in the skill folder except `.clawhub/`, and
    refuses symlinks. Setup puts `node_modules/` (with its `.bin` symlinks) and `samples/` there.
    So after setup, `openclaw skills update` stops with
    `Skill tree contains unsupported entry "node_modules/.bin/clawdhub"`. `--force` updates by
    replacing the folder, which deletes what setup installed. README and SKILL.md now say to run
    setup again. #69 drops the clawhub devDependency, whose `.bin` links were the only symlinks
    there, but OpenClaw would still refuse: after setup the folder no longer matches the
    fingerprint it recorded at install, and `planTrackedClawHubSkillState` stops the update with
    `Skill "strudel-music" has local file changes` (read in OpenClaw 2026.9.8's code, not run).
    Keeping dependencies and samples outside the folder would fix it properly (#67).
  - **Not run:** a request through an agent session (#70, step 4). It needs a model provider.
